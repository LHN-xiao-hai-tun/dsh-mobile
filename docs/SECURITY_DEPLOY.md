# 安全部署指南（SECURITY_DEPLOY）

**DSH Mobile 只是一个手机客户端。安全性主要取决于你如何暴露 DSH 服务。**

本 App 不含 DSH 本体、不预置地址、不采集数据 —— 但如果你把 DSH 裸奔在公网，
它照样能被别人打开。**请按下面的清单部署。**

---

## 1. 首选：组网，不要公网暴露 ⭐

用以下之一，把**手机和电脑放进同一个虚拟内网**：

- [Tailscale](https://tailscale.com/)
- [ZeroTier](https://www.zerotier.com/)
- [WireGuard](https://www.wireguard.com/)
- 其他自建 VPN

这样 DSH 只监听内网地址、**不对公网开放**。即使 DSH 没设 PIN，攻击面也小得多
（**但仍建议设 PIN**）。

---

## 2. 必须：设置强 PIN / 密码 🔴

> ⚠️ 局域网里跑 DSH 时，**务必**设置访问密码 —— 否则**同一网络下的任何设备**
> （包括访客、智能家居、被入侵的邻居设备）都能操作你的电脑。

- 用足够长的随机 PIN / 密码
- 不要用 `1234`、`admin`、`password`
- **不要**在多个服务间复用同一个密码

> `dsh-pocket` 提供 **8 位局域网 PIN**，装上后请开启。

---

## 3. 推荐：启用 HTTPS

- 若 DSH 支持，启用 HTTPS
- 自签证书时，注意确认**证书指纹**后再信任
- **不要在公共 WiFi 下用 `http://` 连接**

参见 [`../SECURITY.md`](../SECURITY.md) 第五节「连接安全机制与取舍」——
当前版本**允许**明文 HTTP（局域网自建的必需前提），但已加分级策略：
私有网段首次确认一次、**公网明文默认拦下**；混合内容已收紧为 `NEVER_ALLOW`，本机敏感配置已加密。

---

## 4. 不要做的事

- ❌ 不要把 DSH 直接 `frp` 到公网**且不设密码**
- ❌ 不要在公共 WiFi 下明文连接
- ❌ 不要把服务器地址 / PIN / token **截图**发到公开渠道
- ❌ 不要关闭系统的锁屏密码

---

## 5. 手机侧建议

- 开启锁屏密码 / 生物识别
- **不要 root**
- 定期更新 DSH Mobile 与 DSH
- **手机丢失时**：第一时间改 DSH 的 PIN / 密码，或在路由器 / 组网层**吊销该设备**

---

## 6. 发现机制说明（v1.2.7 起）

App 有两条发现路径，**都不代表可信**：

| 路径 | 说明 |
|---|---|
| **mDNS / NSD**（快） | 监听 `_dsh._tcp.local`。**需要服务端先广播** —— DSH 本体不广播，用仓库里的 [`tools/mdns-announce.mjs`](../tools/mdns-announce.mjs) 或自建插件。 |
| **子网扫描**（兜底） | 主动探测本子网 `192.168.x.1-254` 的 **3081 / 3080**，并对响应做 HTTP 特征分级。 |

要点：

- **mDNS 可被伪造** ⇒ 发现结果**不会自动连接**，需要你手动确认。
- 连接前请**核对主机名与 IP**（扫描结果会展示，泛词候选还会带「（需确认）」后缀）。
- 广播脚本的 TXT 记录只含 `ver=<版本>` 与 `pin=1`（**是否**需要 PIN 的标记），
  **不含 PIN 本身**，也不含任何凭据。
- mDNS **跨不了网段**：电脑与手机必须在**同一网段**，否则只能靠「扫子网」或手填地址。

---

## 7. 如果怀疑被入侵

1. **立即修改** DSH 的 PIN / 密码
2. 检查 DSH 日志，看是否有**陌生 IP**
3. 在组网层（Tailscale / 路由器）**移除可疑设备**
4. 若确认是 App 自身的漏洞 —— 请走 [`../SECURITY.md`](../SECURITY.md) 报告

---

## 8. 一页速查

| 项 | 建议 |
|---|---|
| 暴露方式 | **组网**（Tailscale / ZeroTier / WireGuard），不要公网裸奔 |
| DSH 密码 | **必设**，且足够强 |
| 传输 | 尽量 **HTTPS**；不要在公共 WiFi 下明文 |
| App 侧 | 保持更新；不 root；手机设锁屏 |
| 发现结果 | **不自动连接** —— 连之前确认主机名 / IP |
| 出事后 | 改密码 → 查日志 → 组网层踢设备 → 报漏洞 |
